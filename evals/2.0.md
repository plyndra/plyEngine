# Eval definition — plyEngine 2.0

Eval-driven definition for the top-down simulation target, written **before** the
first engine unit (`feat/ui-framework` a1). Companion documents:
[`../docs/planning/ROADMAP_TARGET.md`](../docs/planning/ROADMAP_TARGET.md),
[`promotion.md`](promotion.md) (1.x promotion gates, unaffected).

Two rules outrank everything here:

1. **A gate is never relaxed to make a run green.** A wrong criterion is amended
   in the same commit, with the reason.
2. **No model grader decides a factual claim** — licences, determinism, money
   conservation and API freeze are code or rule graders.

## Artefact classes (ADR 0014)

- **Structural hash** — hashes the state that encodes the invariant (rects, layer
  order, quad counts, sort arrays, light samples, sim state). This is what CI
  asserts.
- **Pixel golden** — byte comparison of a rendered frame, allowed **only** in the
  pinned toolchain container and only when explicitly invoked. Never a default
  gate; llvmpipe drifts with Mesa.
- **Rubric review** — a human grader with a named checklist, severity-tagged.
  Used for "does this look like the reference", because `/testpng/` is a style
  reference, not a pixel spec (measured: 10.6k–18.6k unique colours, no clean
  integer period).

## Thresholds

- Capability evals: `pass@3 ≥ 0.90` for reversible units.
- Determinism, save/load, economy-conservation, API freeze: `pass^k = 1.00`.
- R4–R7 are **single-attempt**: a licence or freeze violation is a defect, not a
  flake, and there is no k to average over.
- Rubric review (`E-c3.1`): no FATAL findings; every WEAK either fixed or
  accepted in writing in the milestone note.

## Anti-patterns for this project

- Using `/testpng/` as an image diff (it is not a pixel spec — measured).
- Grading a licence, a determinism claim or a money claim with a model.
- Starting the art gate red "temporarily" (it is scoped to generated assets for
  exactly this reason).
- Relaxing a threshold in the same commit that fails it.
- Treating a passing structural hash as evidence about *look*, or a good-looking
  frame as evidence about correctness. They are different evals.

## Storage

- `evals/2.0.md` — this definition (versioned with code).
- `evals/2.0.log` — append `date eval-id PASS|FAIL evidence` per run.
- A log line names the fixtures and runs it measured. It does not quantify
  universally ("every fixture", "everywhere") unless a single test loops over that
  set: both a2 verifier passes found only that class of error — claims that were
  right in spirit and unmeasurable as written.
- `evals/report-<date>.md` — per-milestone report.
- Structural golden hashes live beside their fixtures (`tests/data/<area>/golden.txt`),
  reviewed as text diffs.
